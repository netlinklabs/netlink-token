# Security Scan Archive — NET (Netlink)

This folder contains raw output from **automated, third-party security scanners** for the NET token contract on Polygon.

**Contract:** `0x0e893B239094A5c573373d44CF1C7D03576b95cb`

## Important: These Are Automated Scans, Not Manual Audits

All reports in this folder are generated by automated tools that analyze the deployed contract and its on-chain state in real time. They are **not** manual security audits performed by human auditors.

- Automated scanners detect common, known vulnerability patterns. They can produce false positives (e.g. flagging a constructor-only mint as "mintable") and cannot fully evaluate business logic, intent, or context.
- Results can change automatically over time as on-chain state changes (holder distribution, liquidity, contract interactions), even with no code changes.
- These reports are provided for **transparency and reference only** and should not be treated as a guarantee of security or a basis for investment decisions.

For the summarized, human-readable version of these results, see the [Audits page](https://docs.netlinktoken.com/docs/docs/security/audits) in the official documentation.

## A Recurring Note: Holder Concentration

All three scanners flag the same item in some form: one wallet holding **~62% of total supply**. This is consistently the largest (often the only) risk indicator raised across every automated tool.

This wallet is a **PinkLock-locked, multisig-controlled** liquidity/treasury allocation — not a freely movable wallet under single-key control. It is documented with its full vesting schedule in `goplus-scan.md`. Automated scanners cannot distinguish a locked multisig allocation from an ordinary large holder, so this flag will continue to appear until the allocation is further distributed or the scanners add native PinkLock/vesting detection.
